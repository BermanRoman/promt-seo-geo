# Проверь сайт

1. **Обновление системы.** `git -C <репозиторий> pull` (только если нет локальных правок в файлах системы), `cd engine && npm install`. Пересобрать сайт: `npm run build` — должен пройти.
2. **Доктор.** `node scripts/doctor.mjs` — всё обязательное с ✓.
3. **Страницы.** `node scripts/lint-drafts.mjs --links $(ls ../workspace/content/explained/*.md | xargs -n1 basename | sed 's/\.md$//')` — битые ссылки в опубликованных разборах: заменить рабочими или убрать.
4. **Индекс.** `node scripts/gsc.mjs inspect` (если есть ключ) — что не в индексе и почему; `node scripts/webmaster.mjs status` — проблемы сайта в Яндексе.
5. **Живой сайт.** Главная, материал, разбор, тема отвечают 200; `robots.txt` и `sitemap-index.xml` на месте; сертификат действует больше 14 дней (`curl -vI` → дата); сайт на сервере совпадает со сборкой (`rsync -nci --delete engine/dist/ <DEPLOY_HOST>:<DEPLOY_DIR>/` — лишних изменений нет).
6. **Заголовки и роботы.** `curl -sI` по главной и по разбору: `Content-Security-Policy`, `Cache-Control`, HTTPS-редирект и 301 на месте (если их нет, а в `.htaccess` они есть — сайт обслуживает чистый nginx, см. навык `infrastructure`, «Веб-сервер»). Роботы нейросетей получают 200 — проверка из навыка `infrastructure`, шаг 8. Журналы доступа читать тем же заходом по SSH, что и сверку в п. 5, а не отдельным.
7. **Скорость.** PageSpeed по главной и одному разбору (pagespeed.web.dev во встроенном браузере): смотреть только реальные проблемы своей вёрстки, не метрики внешнего счётчика.
8. **Живые темы.** Темы, которые не обновлялись больше 2 месяцев, а спрос по ним есть, — в список «обновить».
9. **Безопасность.** Права `.env` и `.secrets` — 600; в git `workspace/` нет ключей (`git -C workspace ls-files | grep -E '\.env|\.secrets'` — пусто).

Мелочь — исправить сразу и выложить. Остальное — человеку списком с предложением, от важного к мелочам. Дата — в `workspace/.deploy/last-checkup`.
