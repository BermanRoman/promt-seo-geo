# Переход на версию 1.2

Редакция от 07.11.2026 переводит систему на общий канон для Claude Code и Codex и переносит в универсальный движок проверенную механику приёмки с живого проекта.

## Основания

База — публичный `promt-seo-geo`, коммит `42817aa6524664827c25344a2db17216898314fa` (версия 1.1).

Перенесены общие решения, принятые при работе живого сайта 27.10–03.11.2026: семантический допуск тем, обязательная вычитка по канону копирайтинга, независимый читатель из поиска, привязка приёмки к SHA-256, честный журнал Wordstat, устойчивые подачи в поисковики и архив, ревью только на чтение. Личное оформление, графика, отдельные серии материалов и решения конкретного автора не переносились.

Это снимок правил на дату переноса; последующие решения в каноне имеют приоритет.

## Что изменилось

- Канон — `AGENTS.md`, `workflow.md`, `roles/`, `.agents/skills/`. `CLAUDE.md`, `.claude/` и `.codex/` стали тонкими входами: правила меняются в одном месте.
- Навыки переехали из `.claude/skills/` в `.agents/skills/`; входы Claude Code под теми же именами остались.
- Роли переехали в `roles/` и дополнены: `copy-editor` (вычитка), `search-reader` (читатель из поиска), `site-reviewer` (ревью).
- В конвейере `material-ready` появились этапы допуска темы, вычитки и читателя; публикация требует действующей записи в `workspace/данные/acceptance.json`.
- «Что это значит?» — самостоятельное объяснение без отсылки к материалу; переход к материалу даёт шаблон страницы.
- Три и более материалов по сюжету — кандидат в живую тему, а не автоматическое решение.
- Материал отмечается обработанным только после итога выпуска.
- `deploy.sh` перед заливкой проверяет приёмку всех опубликованных разборов и тем; страницы, вышедшие до 1.2, закрепляются снимком `acceptance-baseline.json`.
- Старое правило «одна ссылка на базовый материал в тексте» отменено; линтер теперь считает такую ссылку в черновике ошибкой. Опубликованные страницы массово не правятся.
- Канон копирайтинга закреплён по коммиту в `dependencies.json` и проверяется `scripts/check-dependencies.mjs`.

## Что сделать в существующем workspace

1. `git pull`, затем `npm install` в `engine/`, затем из корня системы `node scripts/check-dependencies.mjs --install`.
2. Закрепить уже опубликованные разборы и темы: `cd engine && node scripts/acceptance.mjs baseline` (один раз, при переходе; удалять и пересоздавать снимок нельзя — так узакониваются непроверенные правки). Без этого `deploy.sh` остановится: у старых страниц нет записей приёмки. Изменённая потом страница из снимка выходит только через приёмку.
3. Добавить `.deploy/dist-live/` в `workspace/.gitignore`.
4. Черновики, которые лежат с `draft: true`, до публикации проходят вычитку, сверку, прораба и читателя с записями в реестре приёмки. Уже опубликованные страницы повторно проверять не нужно, пока их не меняют.
5. Карточки допуска нужны для новых тем; для обновления живой темы — карточка с запросом этой темы и решением «обновить существующее».
6. Если в `workspace/voice.md` есть своя типографика (например, точка после закрывающей кавычки в конце абзаца), она остаётся настройкой голоса.
